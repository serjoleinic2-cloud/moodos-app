Ты работаешь как технический аудитор проекта Neyra.

Цель:
Провести РЕАЛЬНЫЙ аудит кода и структуры без предположений и без “придумывания проблем”.

---

# ❗ КРИТИЧЕСКИЕ ПРАВИЛА

* НЕ додумывай
* НЕ предполагай наличие проблем
* НЕ ищи “на всякий случай”
* Если нет проблемы → так и пиши: "проблем нет"

Ты работаешь только с фактами из кода.

---

# 🎯 ЗАДАЧА

Найти только реальные проблемы в:

1. структуре
2. коде
3. логике
4. состоянии (state)
5. доступах (premium)

---

# 🔍 ЧТО ПРОВЕРИТЬ

## 1. СТРУКТУРА

* Есть ли реально неиспользуемые файлы
* Есть ли дублирующие файлы (с одинаковой логикой)
* Есть ли “мертвые” папки

👉 Только если это подтверждается кодом (imports / usage)

---

## 2. КОД (МУСОР)

Найди:

* неиспользуемые переменные
* неиспользуемые функции
* закомментированный код
* временные заглушки (TODO, FIXME, DEBUG)

---

## 3. ЛОГИКА

Проверь:

* не смешаны ли ответственности (UI + бизнес-логика)
* нет ли противоречивых условий
* есть ли потенциальные источники багов

---

## 4. STATE / CONSISTENCY

Проверь:

* есть ли рассинхрон между состояниями
* есть ли данные, которые не очищаются
* есть ли “висящие” состояния

---

## 🚨 5. PREMIUM (КРИТИЧЕСКОЕ)

Контекст бага:

* премиум закончился
* premium-треки остаются в плеере
* их нельзя удалить

Твоя задача:

Найти:

* где хранится premium статус
* где формируется очередь плеера
* есть ли проверка entitlement
* где она должна быть, но отсутствует

Ответь:

* в каком месте ломается логика
* почему треки остаются
* что именно не очищается

---

## 🧪 6. РЕАЛЬНЫЕ БАГИ

Укажи только те баги, которые:

* можно объяснить
* можно воспроизвести логически
* имеют конкретную причину
