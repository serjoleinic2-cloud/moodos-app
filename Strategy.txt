# MoodOS — Development Brief for Claude

## Project Overview

MoodOS is an offline-first Android mood tracking application built with **Capacitor (WebView)**.
All logic is written in **HTML / CSS / JavaScript** inside the `/www` folder.

The application is **single-page (SPA)**. All screens exist in `index.html` as:

```html
<div class="screen" data-screen="name"></div>
```

Navigation is handled via `navigation.js` which dynamically loads screen modules.

User data is stored **locally using localStorage**.
There is **no backend server**.

---

# Core Concept

MoodOS is not just a mood tracker.

The goal is to build a **self-reflection system** that helps the user understand:

* emotional patterns
* triggers
* recovery tools
* personal rhythm

The app already records:

* mood value
* notes
* voice reflections
* photos
* breathing / meditation sessions
* analytics

All data is stored locally.

# Critical Project Rules

These rules **must never be broken**:

1. `closeAllOverlays()` exists only in `navigation.js`
2. `pdf-report.js` must NOT contain `closeAllOverlays`
3. `session-analytics.js` must end cleanly with `}`
4. `onboarding.js` must NOT use `location.reload`
5. `state.js` should not be modified unless absolutely necessary
6. Mood slider and OK button logic exist only in `home.js`
7. `calculateGoldenHour()` returns `{start,end}` object
8. All UI text must go through `t()` translation function
9. PDF reports must always be Russian language
10. Cache busting must be done via `app.js?v=YYYYMMDD`

# FEATURE 1 — Google Drive Backup

Users need the ability to backup their entire mood history.

Requirements:

Backup should include:

* mood_history
* notes_history
* voice_history
* session_history
* photo_history
* user_profile

Backup format:

```
MoodOS-backup.json
```

Data structure:

```json
{
  "mood_history": [],
  "notes_history": [],
  "voice_history": [],
  "session_history": [],
  "photo_history": [],
  "user_profile": {}
}
```

The file should be uploaded to the user's **Google Drive AppData folder**.

Constraints:

* no server
* OAuth via Google Identity Services
* Android WebView compatible

UI:

Settings screen should contain button:

```
Backup to Google Drive
```

Future improvement:

* automatic weekly backups

# FEATURE 2 — Weekly Data Blocks

MoodOS currently stores raw data.

We need **weekly summary blocks** for faster analytics.

Structure:

```
weekly_history
```

Example:

```
{
  weekStart: timestamp,
  averageMood: number,
  entries: number,
  dominantState: string
}
```

Generated automatically when new entries appear.

Purpose:

* faster insight analytics
* yearly comparisons
